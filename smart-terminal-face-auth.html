Terminal UX Case

智能终端人脸授权与语音提示流程

围绕现场终端的身份授权、离线使用、操作日志和语音提示，设计一套从后台配置到终端反馈的完整产品流程。

Face Auth Offline Fallback Voice Prompt PRD
我的角色

负责梳理人员授权、终端同步、离线策略、异常提示和操作记录，让现场流程既能跑通，也能被后台追踪。

Offline离线授权降级
UX终端反馈口径
Problem Framing

现场终端最怕“规则不一致”

后台已授权、终端未同步；网络离线、无法判断权限；操作失败、没有明确提示。这些都会让现场使用者失去信任。

Auth

授权链路长

人员、设备、权限、有效期和人脸模板都需要被统一管理。

Offline

离线场景复杂

终端断网时要决定能否本地识别、如何缓存、何时同步日志。

Prompt

反馈不明确

成功、失败、未授权、离线和设备异常都需要清晰语音提示。

Flow Design

从后台配置到终端反馈

设计重点不是单一识别功能，而是后台、终端和现场人员之间的一致体验。

01

后台授权

配置人员、设备范围、有效期、人脸模板状态和启停规则。

02

终端同步

终端获取授权名单、本地缓存、版本号和同步失败处理。

03

语音提示

为识别成功、未授权、离线、模板缺失和设备异常定义提示口径。

Execution Path

产品文档结构

把复杂现场逻辑拆成状态机和异常分支，研发评审时才不会遗漏边界。

01

定义角色和设备

明确后台管理员、现场人员、终端设备和系统服务的职责。

02

梳理授权状态

覆盖未录入、待同步、已授权、过期、停用和异常状态。

03

补齐离线规则

定义离线可用范围、缓存时长、日志回传和风险边界。

04

统一提示文案

让终端语音、页面提示和后台日志表达同一套规则。

Reusable Insight

可复用经验

终端类产品要优先设计异常场景。正常流程通常简单，现场问题往往出在边界。

Method

把终端体验写成状态机

  • 每个授权状态都要有页面、日志和语音提示。
  • 离线规则必须明确可用边界和同步恢复方式。
